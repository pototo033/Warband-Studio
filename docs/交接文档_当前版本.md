## 1. 这是什么

把旧的 Python 战帮树工坊重做成**以 pack 为中心**的桌面工具：打开 `.pack` → 左边文件树、中间战帮画布、右边种族/派系 + 兵种库；
画布上的所有编辑（加删兵、建组、连升级线、改坐标、建/改页签、换图…）都在内存里攒着，导出时**按表落盘**。

技术栈：.NET 10 / WPF + WebView2（画布是 HTML）、随包附带 `rpfm_cli 4.7.4`（写包/诊断）与 `schema_wh3.ron`；
格式层是**自己实现的 C# 原生读写**（`WarbandStudio.Packfile`，逐字节对拍 rpfm_cli）。

版本约定：`release/WarbandStudio_v<号>/`，**v1.0 留给正式版**，之前一律 v0.1x；`build.ps1` 只保留最近 5 个（次版本 +1，用 `[version]` 解析，别用 double）。
当前 `VERSION = 0.110`，最新产物 `release/WarbandStudio_v0.110`。
**注意**：`packs/`（自动生成的原版/WUU 源包）跟着 exe 目录走，**每个 release 目录第一次启动会自己重建**——
v0.88 的新目录初次启动会用新版代码重抽一遍源包（**UI 来源已改成 WUF**，见 §7.9）（P2 的"框"就是这样回来的）。

## 3. 数据层铁律（踩过的坑，别再踩）

1. **这三张表的键不唯一，必须"拼接读"**（`TableFiles.ReadConcat`）：
   `unit_to_unit_group_junctions_tables`（键=unit，一个兵可属多组）、
   `unit_upgrade_group_ui_links_tables`（键=child_key，一个子组可连多个父组）、
   `unit_upgrade_to_unit_groups_tables`（键=upgrade_key，可跨文件重复）。
   按键合并（`ReadMerged`）会**静默吃行**：实测连线从 751 → 641。
2. **删行只能改原文件**（`RewriteDropping`）：覆盖表删不掉别人的行。
   **新增/改值走覆盖表**：`db/<表>/zzzz_studio_edits`（精英解锁走 `zzzz_studio_elite_unlock`）；
   **坐标/页签**优先**就地改原文件**（包里已经有这一行的那个文件），只有「包里哪都没有的组」才补 `zzzz_studio_layout` 覆盖表（v0.115，见 §7.31）。
3. **升级箭头（游戏里画的线）读 `unit_upgrade_group_ui_links_tables`（C1 结论，用户拍板）**；
   **能不能升级**读 `unit_upgrade_to_unit_groups_tables`（不画线）。原版实测 `parent_key = base_unit_group`、`child_key = target_unit_group`（738/747）。
4. **页签归属严格按表单推导（并集，不做多数票）**：
   `页签(ui_infos.category) → 组 → 兵(junction) → 该兵能被哪些派系用（军事组 junction / 专属授权 / 建筑招募三路）→ factions.subculture`。
5. **建包时不要照搬原版表**：只放当前 mod（WUU）自己的表；缺的表就**不写**（工具需要时另建 `studio_*` 覆盖表）。
   原版 `data\db.pack` **只当运行时数据源**（兵牌/中文名/派系/成本金额等，见 §6）。
6. **成本 `resource_cost` 是 Key**，金额在 `resource_costs_tables` 且**为负**；下拉显示成 `key（-400）`。
7. **精英/RoR 入池自动解锁**：写 `main_units_tables/zzzz_studio_elite_unlock`，把 `restrict_xp_gain_in_campaign` 改 **false**（它不控制初始等级）。
8. **页签在游戏里"有内容才显示"**：twui 的 `ContextVisibilitySetter` 回调要求"该 category 下有组"——
   所以新建页签时会**自动放一个空组**（`studio_tab_<key>`），否则游戏里看不到页签。

## 4. 代码约定（写代码时照这个来）

- **注释一律中文**，写"为什么"不写"是什么"；改过的坑要在注释里留一句原因（例如步长 46 那条）。
- **补丁方式**：不要再用手工行替换改代码 —— 本会话因此出过三次事故（删空 `WarbandNewTab.cs`、多删 `</div>`、删掉 `for` 循环行）。
  规则：**先读文件确认锚点 → 用 Edit/Write 工具改 → 立刻编译**；改 `canvas.html` 后**必须跑 `node tools/check_canvas.js`**
  （抽 `<script>` 做语法检查 + id 防呆；解析期错误不触发 onerror，表现只是"画布空白"），涉及面板再跑 `node tools/check_canvas_panel.js`，最后实跑看日志。
- **落表三条**（v0.85 起，`WarbandAmender` 里都是这个次序，改它时别破坏）：
  ① 每一步读文件都走 `CurrentBytes(pack, repl, 路径)` —— **本轮缓冲（repl）优先**，再退回原包
  （否则"先加后删""先重命名后建页签"会读旧内容，把本轮写入整块盖掉）；
  ② 要处理的文件清单走 `TablePaths(pack, table, repl)` —— 原包里的 + 本轮新写进 repl 的；
  ③ `AddRows` 带 `keyCols`：键表（routes/groups/costs/categories）同 key 以**最后一条**为准；
  **组合键的表必须 `ReadComposite`+`MergeComposite`**（军事组授权 unit+military_group、专属授权 key+faction、
  成本↔资源池 factor+resource_cost、**兵种变体 faction+unit** —— 第一个键常是可选/空的，按键合并会把行吃光）；
  键不唯一的表（junction/links/军事组授权）按整行或组合键去重，追加而不是覆盖。
- **画布页面自检**：`canvas.html` 顶部有 `window.onerror` / `unhandledrejection` 上报（日志里 `{type:'jsError'}`）；
  启动时还会回报 `{type:'domCheck', bad:[…]}`（检查 `npOk/npClose/mButtons/ctxRow1` 是否在各自浮层里）。
  **语法错误是解析期失败，不会触发 onerror** —— 所以 `node --check` 不能省。
- **编辑只有两个入口**：画布消息 → `MainViewModel.ApplyCanvasEdit(json)`（按 `type` 分发）；表/文件操作走 `Backend`。
  加新功能＝加一个 `case` + 一个 `Backend` 方法 + 在 `WarbandAmender` 里落表。
- **编辑数据是按包分开的**（`Backend.Edits` 按 packPath 存），切画布/换包不会串台；`PushUndo()` 在每次编辑前压快照（Ctrl+Z 撤销）。
- **命名**：工具生成的东西一律 `studio_` 前缀（`studio_new_*`/`studio_tab_*`/`studio_group_*`/`studio_cost_*`/`studio_split_*`）；
  **覆盖表文件名必须排最后**：`zzzz_studio_edits` / `zzzz_studio_layout` / `zzzz_studio_elite_unlock` —— 同一张表的多个文件按文件名的加载顺序定胜负，名字排不到最后就会被 MOD 自己的文件顶掉（§7.31）。
- **日志**：关键动作都要 `Log?.Invoke(...)` 一行说清"做了什么、落在哪、待导出"；诊断信息（叠加编辑、军事组、页签位置）也进日志，方便无头排查。
- **无头验证**：改完先 `dotnet build`，再启动 exe 看 `%APPDATA%\WarbandStudio\app.log` 里的 `rendered` / `domCheck` / `jsError` / `画布自检`；
  涉及落表的改动必须跑 `verify_native.py`。

### 4.1 状态变更铁律（v0.117 起，**新功能一律照这个自检**）

> **"能不能做出来"只是第一问；第二问必须是"它被进一步编辑时会不会出错"。**
> 这个项目里绝大多数实测 bug 都不是"没实现"，而是**只考虑了"加入"、没考虑"删除 / 变更 / 再变更"**。
> 新功能提交前，把下面三态各走一遍（验收里也要留一条回归）：

1. **加 → 再改**：同一目标再操作一次（改坐标 / 改金额 / 换图 / 改页签）会不会把前一次的写入吃掉、或叠出两份？
2. **加 → 再删**：删掉之后，派生数据（标记、缓存、索引、引用行、文件树红标）有没有一起撤销？
3. **删 → 再加**：删掉再加回来，会不会出现"多一条 / 少一条 / 指向不存在的东西"？

**历史上踩过的坑（都是这条铁律的反面教材，简要列在这，细节在 §7）**：

| 症状 | 只考虑了什么 | 漏了什么 | 记在哪 |
|---|---|---|---|
| 拆组"原组不变、多出一个复制品"；连线"点了删除删不掉" | 编辑集只往 Add 里记 | 同一对**先加后删**要互相抵消（读侧"先减后加"把删掉的又复活） | §7.31 |
| 拖坐标 / 移页签"重新加载又回退" | 只想"写一张覆盖表" | 覆盖表**抢不过**作者按种族文件的加载顺序；已有行要**就地改** | §7.31 |
| 合并后组（连带精英兵）消失、游戏报 invalid record | 只写"新组 + 新行" | 组被删了，**引用它的旧行**没跟着清（悬空引用） | §7.30 |
| 自建页签进游戏直接没有 | 只写了图（换图那一步） | 没检查页签本体（categories 行 / twui 块 / 自动空组）在不在 | §7.32 |
| 换图后画布/对话框显示"当前是空的"或旧图 | 只想"图写进包了" | 缓存（`SkinAssets` / 皮肤缓存）没随写路径失效；保存重开后拿着**已关闭的包** | §7.31 / §7.32 |
| 换图后**旧的"在用"标签还挂着** | 标记只按"文件名像不像页签 key"算 | 标记要**按当前状态算**：换图后旧图不再供图，标记该自动撤销（v0.117 起 `ArtSuppliers`） | §7.34 |
| 以为"把 SKV 的图换掉了" | 只报"换图成功" | 界面没写清楚**只复制不改名**；选图时也没提示"这张正被谁用着" | §7.33 |

**配套检查表（写新功能时照着自己问）**：
① 我改的东西有没有**派生状态**（标记 / 缓存 / 索引 / 引用行 / 文件树红标）需要在同一处撤销或失效？
② 界面上的"当前 / 在用 / 已应用"这类文案是**算出来的**还是**存下来的**？算出来的才对。
③ 落表的每种行（新增 / 改值 / 删行）在**再编辑**时走哪条路？会不会两份数据抢同一个 key？
④ 缓存有没有版本或失效钩子（改完还看得见旧图 = 必然踩）？
⑤ 验收里加一条"改 → 删 → 再改"的回归，而不是只测首次成功。

### 7.11 v0.91：切种族后"整页黄标"（真根因：黄标是渲染时烤上去的）

- **现象**（用户日志实证）：开包后逐个点种族/派系，**当前页的牌全是黄标**：
  `{"type":"filter","page":"SLAANESH","scope":"种族 wh3_main_sc_slaa…","shown":43,"foreign":43,"foreignTab":false}`；

- **根因**：黄标（"不属于当前军事组"）和专属角标原来是在 `renderWarband` 里**按当时的 filterRace/filterFaction 写好 class 和 DOM 的**；
  而切种族/派系**不会重渲染**（数据没变，只做显示过滤）→ 上一次选择时烤的标一直留在牌上，
  于是"整页黄标"（而且跨页签、跨画布都一样：每张画布只在数据变化时渲染一次）。
  中途只要发生一次重渲染（换包/编辑/切回），标就"自己好了"——这正是"同一页第二次点是 0"的原因。
- **修法**：角标改成**实时算** —— 渲染时只把判断数据挂在卡上（`_gR`/`_gF`/`_excl`）+ 建一个 `.bdg` 挂载位，
  由 `updateBadges()` 在**每次 `applyFilter` 开头**按当前过滤重算（切种族、切页签、切画布都走这条路）。
  空组占位框没有角标位，自动跳过。
- **回归测试**：`node tools/check_canvas_panel.js` ⑧（4 条）——"带着不匹配的种族渲染 → 切到真正属于它的种族 →
  本页可见的牌**不该**有黄标"。这条在旧代码上会失败（烤的标还在）。
  为此给离线 DOM 桩加了迷你选择器 + 元素注册表（`#tree .card` / `#tree .card.foreign` 都能查）。
- **注意**：v0.89 的"军事组/专属授权改组合键合并"是**另一件事**（口径修正，实测只差 137 条），
  与这次的黄标 bug 无关，两者互相独立。
