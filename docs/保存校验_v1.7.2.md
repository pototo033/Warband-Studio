# v1.7.2 保存校验

保存和导出的统一顺序：完成所有落表 → 写独立临时包并检查索引 → 内置 RPFM diagnose → Error 为零才原子提交。诊断启动、缓存生成、JSON 解析或报告识别失败均不提交，临时包在 finally 清理；原包与待保存编辑保留。

RPFM 4.7.4 JSON 只序列化 `report_type`，不含 `level`。`RpfmDiagnosticReport` 严格按照同版 `rpfm_extensions/src/diagnostics/*::DiagnosticReport::level` 转换分级，覆盖 DB、Loc、Config、Dependency、Pack、AnimFragmentBattle、PortraitSettings、Text；未知类型停止保存。更换 CLI 时必须同时核对分级映射。

`NoReferenceTableNorColumnFoundNoPak` 为 Warning；`InvalidReference` 为 Error。缺少 AK 专有码表不会被额外提升为错误。`ExportReferenceValidator` 保留供旧探针单独排查，已退出正式保存链路。生成缓存不传 `-a`，缓存指纹升级为 `v2-game-only`，避免复用旧的带 AK 缓存。

生产路径默认使用真实 RPFM。离线测试可显式注入临时包诊断器，避免虚构游戏目录依赖真实引擎；不存在按设置或环境自动跳过校验的开关。

验证（2026-10-20）：

- 127 项 .NET 回归（71 核心 + 56 界面后端），覆盖两种 Rust 枚举编码、Error/Warning/Info、无效报告、提交失败和临时包清理。
- `probe save-gate-test <来源.pack> <游戏data/db.pack> <本轮测试目录>`：真实内置 CLI 与游戏数据，雪乃包 0 Error、60 Warning 放行；注入不存在的 pooled_resource_factor 后，已有目标和新目标都被 Error 拦截，目标哈希与待保存编辑不变。
- 新建专用缓存的命令日志确认无 `-a`；首次诊断与后续复用通过。
- `verify_native.py` 四大项通过，未改写正式 MOD 或游戏数据。
