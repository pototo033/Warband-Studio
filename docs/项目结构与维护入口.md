# 项目结构与维护入口

## 项目依赖

`Ui` 是桌面壳与交互入口；`Pack` 负责战帮编辑和导出；`Packfile` 负责原生包与表编解码；
`Rpfm` 负责外部诊断工具；`Core` 提供目录定位；`Editors` 提供表编辑模型。
命令行验收放在 `tools/WarbandStudio.Probe`，回归测试放在 `tests/WarbandStudio.Tests`。

## 布局维护

保留左侧工程与素材、中间画布、右侧派系与兵种库的槽位；分栏仍允许拖动。
工具栏按工程、保存、工具分组；状态信息只在底栏显示。
窄窗口下操作换行，欢迎页和全局选项滚动；素材库操作不横向溢出。
主窗口最小尺寸为 1100×700，右侧默认宽度 300。

修改后立即编译；涉及画布时运行两个 canvas 检查；涉及落表时运行原生四项验证。
构建版本后启动验收，日志需出现空状态收尾和 `domCheck bad=[]`。

RPFM 依赖缓存由当前内置 CLI 在 `%LOCALAPPDATA%/WarbandStudio/cache/rpfm` 内生成，按来源指纹隔离；
只在 .pak1/.pak2/.pak3 全部生成后标记可用，不读取其他 RPFM 版本缓存。安装 AK 时自动纳入 raw_data/db 码表。
导出在写临时包和原子提交前校验最终原包+repl-删除集合；错误或缺来源都中止，不以“跳过体检”放行。

## 数据安全与回归入口

更新安装复用已有未保存编辑确认；下载完成并验证后才询问处理编辑，旧进程退出后才替换程序。
仅 app.zip 程序/Web/schema 文件可覆盖；工程、Pack、设置均保留。失败恢复与日志独立于 MOD 导出事务，测试使用隔离安装副本。

`Pack/AtomicFile.cs` 提供同卷原子提交、配置写入和导入复制；保存与还原先校验临时包、完成备份，再替换目标。
工程归属保存在 `PackSession.ProjectDirectory/ProjectKey`，不能从当前全局工程推断另一个会话的保存位置。
后台读使用 `CaptureReadContext/Read`；界面发起的读取还须通过 `ReadCurrentAsync` 丢弃过期结果。
修改编辑集使用 `Backend.Edit`，失败回滚、空操作保留重做；成功后界面统一刷新并安排所属会话自动保存。
表格/兵组重命名先将当前语义编辑落成内存检查点，再按 schema 同步直接与间接 DB 引用。
`WarbandEdits.TableReplacements` 和原文件删除集合共同进入保存及深拷贝撤销快照；读取用 `PackArchive.OpenView`，不能提前改源包。
表页签用包路径+内部路径绑定；保存/关闭/切页等待单元格提交，保存成功后延续现有清空撤销历史规则。
有测试须询问用户是否完成，确认后清理该轮缓存；回归代码、正式构建、备份、源包与指定成功基线保留。

核心格式和工程存储回归位于 `tests/WarbandStudio.Tests`，会话、失败保存、多资源成本及来源隔离回归位于
`tests/WarbandStudio.Ui.Tests`；后者仅创建独立临时测试包，设置不写用户配置。
