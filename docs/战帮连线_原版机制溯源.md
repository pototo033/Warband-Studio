## 已确认的调用链

当前游戏 `data/ui3.pack` 中的 `ui/campaign ui/warband_upgrades.twui.xml` 已重新提取核对，SHA256 为 `49BF89F134FD6C6C21E74E3209AB613E75F69B8403EF79A25C50F289F1840E24`，与工作区 `源码/战锤9.0/ui/campaign ui/warband_upgrades.twui.xml` 一致。

`upgrade_tree` 的 `TreeCallback` 请求：

```text
UnitUpgradeManagerContext.UnitGroupUpgradesTree(
    UnitUpgradeManagerContext.ForceUnitGroupUpgradesList(...).Filter(Category == ...)
)
```

CA metadata 将 `CcoCampaignUnitUpgradeManager.UnitGroupUpgradesTree` 的返回类型定义为 `TreeData`。CA callback 文档说明 `TreeCallback` 是通用的科技树/家族树等树形绘制回调，由程序传入 `TreeCallbackData`，条目使用 `TreeEntryCallback`。不是 Lua 自己绘制这段升级连线。

当前原版模板包括：

| 组件 | XML 中能确定的内容 |
| --- | --- |
| template_slot_entry | 模板尺寸 46 × 100 |
| template_branch_horizontal | 横线模板尺寸 63 × 13，可横向缩放 |
| template_branch_vertical | 竖线模板尺寸 13 × 50，可纵向缩放 |
| template_branch_end | 箭头模板 user property：line_end_offset=3、line_start_offset=-9.0 |

这些是模板初始尺寸及箭头属性，不能当成最终每段线长。`3 - (-9) = 12` 也不能证明出端短线为 12 像素，公开资料没有给出这种等式的语义。

## 对短线与 mid_link_offset 的证据边界

- DB 的 `unit_upgrade_group_ui_links` 存储父子端口、父子端口偏移及 `mid_link_offset`。当前 schema 中 `mid_link_offset` 是 F32、默认 0、说明为空，没有基础短线 12 的定义。
- 当前原版 Lua 脚本中未找到 `UnitGroupUpgradesTree`、`mid_link_offset`、`TreeCallbackData` 或 `line_start_offset` 的计算实现。
- `CcoTreeLink`/`CcoTreeLinkWithContexts` 公开父子上下文与组件上下文，不提供基础短线长度或转折公式。
- 可读源码和 CA 导出接口到原生 `TreeCallback` 即止，当前工作区没有其引擎实现；无法据此确定固定 12、固定 20、半兵牌宽或端口偏移的精确公式。
- 工坊 Git 历史中，v1.2 重构首个提交 `c9d9b2d` 的 `canvas.html` 已含 `STUB = 12`；冻结的 Python 旧工具 `tools/warband-tree-studio/web/app.js` 使用 `STUB = 14`。没有发现把 12 从游戏 XML 读取出来的代码。
- v1.7.9 按截图假设改为 40/2=20，但尚未实机校准。v1.7.10 保留预览近似，不把 12 或 20 宣称为原版常量，不迁移已有落表值。
