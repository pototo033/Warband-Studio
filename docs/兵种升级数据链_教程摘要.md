# 兵种升级数据链 · 教程摘要与冲突处理规则

> 来源：用户提供的《兵种升级数据库》教程（RPFM 视角）。
> **规则（用户强调）：教程与工坊既有标准/实现一旦冲突，一律先问用户，不许自行取舍。**
> 本文件既是教程摘要，也是冲突台账。

## 一、处理冲突的规则（硬性）

1. 发现"教程说的"和"我们已实现的/已定的标准"不一致 → **停下来问用户**，不要自行选择；
2. 用户拍板后，把结论写回本文件（冲突台账 + 结论），并同步到 README / UI 约定；
3. 已定标准里最容易被教程挑战的两条：**页签（categories）创建方式**、**画布连线的数据源**。

## 二、数据链（一条路线的完整构成）

```
main_units
  ↓ unit_to_unit_group_junctions（unit = main_units 的 key；unit_group = 组 key）
基础 unit_upgrade_group
  ↓ unit_upgrade_to_unit_groups（upgrade_key / base_unit_group / target_unit_group）
目标 unit_upgrade_group
  ↓ unit_to_unit_group_junctions
目标 main_units

附加层：
  建筑要求（unit_upgrade_to_building_level_requirements.building_level）
  科技要求（unit_upgrade_to_tech_requirements.technology）
  资源成本（路线里的 resource_cost 是 **Key** → resource_costs_tables）
  最低等级 / 升级后扣级（required_rank / subtracted_rank）
  UI：分类（ui_categories）→ 位置（ui_infos: x/y/category）→ 连线（ui_links）
  Effect：campaign_bonus_value_ids_unit_upgrade_to_unit_groups + effect_bonus_value_unit_upgrade_to_unit_group_junctions
```

## 三、逐表要点（精简版）

| 表 | 关键字段 | 要点 |
|---|---|---|
| `unit_upgrade_groups_tables` | `unit_group` | 组是**路线节点**，不等于兵种；一组可含多个等价单位 |
| `unit_to_unit_group_junctions_tables` | `unit`(=main_units key) / `unit_group` | **最容易漏**：只建组和路线、不把单位接进组 → 游戏不知道起点/终点 |
| `unit_upgrade_to_unit_groups_tables` | `upgrade_key` / `base_unit_group` / `target_unit_group` / `resource_cost` / `required_rank` / `subtracted_rank` | 路线本体；`resource_cost` 填 **Key 不是数字**；`required_rank` 是**部队等级**不是人物/建筑等级 |
| `resource_costs_tables` | `treasury_cost` | 金额在这里，且**为负**（扣钱方向，如 -500）；`expenditure_type=RECRUITMENT` 等 |
| `unit_upgrade_to_building_level_requirements_tables` | `unit_upgrade` / `building_level` | 接**具体建筑等级**；目标派系得真能拥有该建筑 |
| `unit_upgrade_to_tech_requirements_tables` | `unit_upgrade` / `technology` | 科技必须在目标派系实际用的科技树里；**AK 导出的 `technology_unit_upgrades_tables` 是空的，别用** |
| `unit_upgrade_group_ui_categories_tables` | `category` | 原版数据只有 **KHORNE / NURGLE / SLAANESH / TZEENTCH / UNDIVIDED**（全大写）；新造 key 不会自动让派系获得界面 |
| `unit_upgrade_group_ui_infos_tables` | `unit_upgrade_group` / `x` / `y` / `category` | 只管**布局**，不决定升级条件 |
| `unit_upgrade_group_ui_links_tables` | `parent_key` / `child_key` / `parent_link_position` / `child_link_position` / 三个 offset | **纯视觉**：加线不会创建升级路线；缺线不影响功能 |
| `effect_bonus_value_unit_upgrade_to_unit_group_junctions_tables` + `campaign_bonus_value_ids_unit_upgrade_to_unit_groups_tables` | Effect / Bonus Value / `upgrade_key` | Effect 按 `upgrade_key` 影响某条路线；具体含义要从**有效原版 Effect 反查**，别按 key 名字直译 |

**派系接入边界**（教程）：建了组/路线/UI 数据，派系仍可能看不到入口 —— 机制没启用、单位没接进基础组、
分类/界面没接入、资源/建筑/科技对该派系不可用、脚本初始化等。**最稳妥是在已拥有该机制的派系里加/改路线**，
"整套机制移植给不用的派系"属于更大的战役机制工程，不能只靠改表完成。

### C1 结论（已定）

- **画布箭头 = `ui_links_tables`**：这是游戏里**真实会显示**的箭头，属于 UI 层绘制效果；字段用
  `parent_key` / `child_key` / `parent_link_position` / `child_link_position` / 三个 offset 还原方向与出入口。
- **升级关系 = `unit_upgrade_to_unit_groups_tables`**：决定"能不能升级成"，**不画线**；用于
  校验/体检/将来编辑路线（箭头只忠实还原 UI）。
- 体检补两类报告：**有路线没连线**（能升但界面看不到箭头）与**有连线没路线**（画了线但升不了）。


## 实测对照（v1.1，2026-09-29）

拿原版 `data/db.pack` 与用户战帮包（`pototo_warband_corpses_2_full.pack`）各跑一遍，数字如下 ——
**连线数与路线数不相等是正常的**（C1 结论：一个画线、一个决定能不能升）：

| 数据 | 原版 db.pack | 用户战帮包 |
|---|---|---|
| 组（`unit_upgrade_group_ui_infos_tables`） | 66 | 843 |
| 连线（`ui_links`，去重后的组对） | 55 | 747 |
| 路线（`unit_upgrade_to_unit_groups_tables`，去重后的组对） | 153 | 1205 |
| 有路线没连线 | 98 | 467 |
| 有连线没路线 | 0 | 9 |
| 页签（`category`） | 5 | 26 |

- **有连线没路线**的 9 条就是教程警告的那类问题（界面画了线、实际升不了），例如
  `Yukino_Dwf_Inf_Quarrellers_2 → Yukino_Dwf_Inf_Thunderers_1`、`Yukino_Skv_Inf_Night_Runners → Yukino_Skv_Inf_Clanrat_1`；
  工具只在日志里逐条列出，不自动改。
- **出入口位的取值**：实测只出现 1/2/3/4 四个值，几何关系反推 = 1 上、2 右、3 下、4 左（见上）。

### 一个必须记住的坑：这三张表**不能按键合并**

`unit_to_unit_group_junctions_tables`（键=unit）、`unit_upgrade_group_ui_links_tables`（键=child_key）、
`unit_upgrade_to_unit_groups_tables`（键=upgrade_key）在 RON 里都只标了一个 key，但**真实数据里键不唯一**：

- junction：989 行 / 972 个唯一 unit —— 17 个兵同时属于两个组；
- ui_links：751 行 / 747 个唯一组对 —— 4 行完全重复（同一个子组连不同父组是常态）；
- routes：1227 行 / 1205 个唯一组对 —— 同一个 upgrade_key 可在多个文件里各写一条。

按 key 合并（后赢）会**静默吃掉这些行**（实测连线从 751 掉到 641）。工具里这三张表走
`TableFiles.ReadConcat`（拼接 + 整行去重），其余表仍走 `ReadMerged`（按键覆盖）。
