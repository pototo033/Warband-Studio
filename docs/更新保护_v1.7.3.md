# v1.7.3 更新保护

更新包下载、验证完成后，先提交正在编辑的表格单元格并取消待触发的自动保存，再锁定交互、创建恢复快照。快照包含所有打开的编辑包与参考兵种包、工程绑定、当前编辑、撤销/重做、表格内存缓冲、外部换图素材、新页签素材及活动文档。该流程不调用保存/导出，不要求未完成编辑通过 RPFM。

快照放在 `%LOCALAPPDATA%\WarbandStudio\recovery\<独立ID>`，包含未改写的 Pack 底本、素材和带格式版本的 manifest。所有文件计算 SHA256，文件和清单 flush 到磁盘、重新反序列化验证后才原子公布 pending 指针。更新器只清理 updates 下的下载/安装缓存，不触及 recovery。准备失败不退出；取消安装解除锁定并撤销本次 pending，保护快照仍保留。

新程序初始化后按安装目录读取 pending；原进程尚存活或已被另一个恢复进程认领时不重复加载。先验证所有快照文件；原 Pack 哈希不变就打开原路径，变化或缺失则打开独立底本副本，解除该副本的原工程目录绑定并提示用户另存，避免覆盖外部修改。恢复成功才删除 pending 指针；底本、素材与历史快照继续保留。失败保留 pending 与文件，下一次重启可重试，不覆盖用户 Pack。

`UpdateRecovery.Json` 对 WarbandEdits 的只读集合使用 Populate，并包含 ValueTuple 字段；新增编辑类型时必须通过“所有编辑集合往返”的回归。正式恢复仍走当前 Backend 的隔离会话、来源缓存与表格读取管线。

验证：135 项 .NET 回归（71 核心 + 64 界面后端），包含 8 项新增更新恢复用例；真实 Windows 安装助手验证清理时保留独立 recovery 数据。跨进程启动验证记录放在 `.tmp/update-recovery-v1.7.3`，本轮测试完成须用户确认后清理。

兼容边界：v1.7.2 及更老的程序不具备写恢复快照能力，因此首次安装本版前仍需保存；从本版发起的后续更新才能自动暂存、重启恢复。该机制不是普通编辑过程的持续崩溃备份。
