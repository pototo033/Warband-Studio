# v1.7.4 授权重复与范围扩展修复

旧问题分两层：GrantUnit 不查询已经生效的授权，加兵/拆组/移动建组会重新排队；军事组 AddRows 仅在目标工坊文件去重，同一组合键位于作者其他文件或原版时仍写一份。种族模式还会补齐全部军事组，使已有局部授权被扩展。

按用户于 2026-10-21 确认的规则，自动加兵使用 EnsureUnitPermissions：先合并原版和当前包的完整军事组/专属组合键，读取当前表格缓冲与删除集合，再叠加待保存增删；已有当前种族/派系的军事组或正向专属许可则保留。没有对应归属才补授权。显式 GrantUnit 继续允许补齐，但只排缺失项；删除后重新分配取消删除，不为本来存在的行再加副本。拆组、移动建组不授权，连线不授权。

写入端再次对原版、作者所有军事组文件和本轮 repl 去重，拦住旧会话/更新恢复里的重复队列，不以包内单一目标文件作为存在性依据。不会盲删已经存在的其他有效军事组授权。

另修复删除优先边界：已经删除的表格文件不能从旧 TableReplacements 回灌到 repl；PackWriter 补新增条目时也要遵守 dropPaths。明确的后续语义新增仍可重新生成文件，不改变页签改名让位时的“本轮生成内容胜过旧删除标记”规则。

验证：144 项回归（72 核心 + 72 界面后端），涵盖新单位、已有局部归属、专属 allowed=true/false、显式扩展、组合键去重、连续保存、撤销重做、删除文件、旧缓冲与打开/绘图/拆组/移动/连线。作者已修正样本的只读验证：打开编辑数 0；已有帝国单位加兵/连线新增授权 0；重放 487 个现有作者组合键，写入权限文件 0；源包 SHA256 不变。作者最新样本的 verify_native.py 四大项通过。

原始 58 条错误已被作者修正，未逐条复现其具体诊断类型；以上为本机源码与修正样本可以直接验证的结论。该样本未写回，也未替换工作区或游戏 Pack。本轮缓存 .tmp/permission-grants 暂留供复测。
