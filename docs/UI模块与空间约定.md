# 新工具 UI 模块与空间约定

> 这份是**设计约定**（用户拍板的），改界面先看它。
> 原则：**功能照老工坊（战帮树工坊）的做法，UI 按这里的布局；整体模块化，四周预留槽位。**

## 一、空间划分（四周留槽 + 中间画布）

```
┌─────────────────────────────────────────────────────────────┐
│ 菜单 / 工具栏                                                │
├──────────┬──────────────────────────────────┬───────────────┤
│ 左栏      │           中间：战帮画布           │ 右上：种族/派系 │
│ Pack 文件 │   ┌──────────────────┐            ├───────────────┤
│ 树        │   │                  │ ┌────────┐ │ 右下：兵种库   │
│（pack 名为│   │   兵牌树（画布）    │ │页签列  │ │（实时读 DB、  │
│  最高一级）│   │                  │ │悬空浮层 │ │ 按派系分类）  │
│          │   └──────────────────┘ └────────┘ │               │
├──────────┴──────────────────────────────────┴───────────────┤
│ 左下：分页面板（① 全局选项 ② 诊断·引用）     底部：状态栏      │
└─────────────────────────────────────────────────────────────┘
```

**预留槽位**（现在放占位符/空容器，接新功能时直接填）：

| 槽位 | 现状 | 用途（已定 / 待定） |
|---|---|---|
| 左上 | Pack 文件树 | 已用 |
| 左下 | 分页面板（全局选项 / 诊断·引用 / **UI 素材库**） | 已用，可加页（模块化，每加一个模块多一页） |
| 中 | 战帮画布（WebView2） | 已用 |
| **画布内右侧** | **页签列（悬空浮层）** | 浮动在画布右侧上方，不占画布布局；切页签只画该页签的组 |
| **右上** | 种族 / 派系选择 | 种族由页签归属推（raceOfCat），派系取该种族的派系列表 |
| **右下** | 兵种库 | **实时读 DB**（不用老工坊的 units_*.json），**按派系分类** |
| 底部 | 状态栏 | 已用；后续可加"进度/日志条" |
| **顶部（顶栏以下）** | 空 | 预留：多 pack 标签栏（同时打开多个表单） |
| **底部（状态栏以上）** | 空 | 预留：详情/引用面板 |

## 二、模块化约定

- 每个面板 = 一个独立模块（一个 VM + 一个 UserControl），通过**槽位名**挂到上面的位置；
- 模块之间只通过 Backend 的公开方法通信（不互相引用）；
- 新增模块的步骤：写 UserControl → 在对应槽位的容器里加一行 → 需要数据就加 Backend 方法；
- 画布内部的东西（页签浮层、未来的筛选条）也按模块做，挂在画布容器上而不是写死进 HTML。

## 三、兵种库（右下）——实时读、按派系分类

**数据来源**（全部原生读，跨"本包 + 原版"合并）：

```
派系（factions_tables.culture → 种族）
  → 该派系能拿到的兵：units_to_groupings_military_permissions_tables（授予）   ← 是"授予"不是"限制"
    ∩/∪ units_to_exclusive_faction_permissions_tables（派系专属授权，列了=允许）
  → 兵种信息：main_units_tables（名册层） + land_units_tables（战场层）
  → 显示名：unit_variants_tables.name（本地化 key）→ loc（若配置了 loc TSV 就查，否则显示 key）
  → 卡图：unit_variants_tables.unit_card → ui/units/icons/<unit_card>.png（见 README 的解析链）
```

- **已实现（v0.1x）**：右上 = 种族/亚文化 → **传奇派系**两级树（种族名取 `cultures_subcultures_name_<亚文化>`、
  派系名取 `factions_screen_name_<派系>` 的 loc 中文名，鼠标悬浮显示真实 key；**非传奇派系合并成一条「通用」**，
  传奇判定 = 出现在 `frontend_factions_tables`（= 新战役界面能选的派系），原版共 110 个）；
  顶上一条「全部兵」；右下 = 兵种库，按选中派系**实时读 DB**（三路并集后与 `main_units_tables` 求交）：
  ① `factions.military_group` ↔ `units_to_groupings_military_permissions_tables`（主路）
  ② `units_to_exclusive_faction_permissions_tables`（专属授权，allowed=true）
  ③ `building_units_allowed_tables`（faction + enabled=true，招募来源）；
- **交互**：兵种库**双击**一张牌 → 画布新开一组（老工坊是拖拽）。WebView2 与 WPF 是两套东西
  （空气墙：WPF 元素盖不住 WebView2，反向的鼠标事件也接不到），拖拽跨不过去，所以先用双击；
- 尚未落表：新组要写 `unit_upgrade_groups_tables` + junction + 组坐标，**写回在下一步**（现在只在内存里记着）；
- 显示名还没接 loc（现在显示 key）；

## 四、画布（中）——只画"当前页签 + 当前派系"的兵牌树

- 页签来自 `unit_upgrade_group_ui_infos_tables.category`（只列当前坐标层真有组的页签 + 自建页签）；
- 组按 `x/y` 落位，同组多兵 +46 并排；
- **箭头来自 `unit_upgrade_group_ui_links_tables`**（C1 结论：这才是游戏里真实显示的线）。出入口位
  `child_link_position` / `parent_link_position` 用 1=上 2=右 3=下 4=左（由原版 55 条连线的几何关系反推：
  `3→1` 最多 = 子组在下、父组在上），三个 offset 只微调中段；**能不能升级**看
  `unit_upgrade_to_unit_groups_tables`（同表给成本 Key 与等级门槛），它**不画线**；
- 体检只报告两类不一致：**有路线没连线**（能升但界面没线）、**有连线没路线**（有线但升不了）；
- 派系过滤默认"全显示 + 专属角标"，另给一个"只显示本派系可得"的开关；
- 拖动改坐标 → 导出**就地改原文件**里那一行（包里没有行才补 `<项目key>_Upgrade_<页签>` 文件，v1.5.9 起，原 `zzzz_studio_layout`）。

## 五、导出（保持现有 + 待补）

已实现：精英解锁 · 四神开关 · 坐标覆盖 · **引用体检（以原版为准）**。
待补：**兵种库加进画布的写回**（groups + junction + 坐标一次落盘）、**派系专属授权**（`unitXfPlus`）、**剔除无效记录**开关（老工坊有：
把解析不了的引用行真删掉——例如某些 mod 里 8.x 时代的旧机制引用，如 `blood_kiss_other`）。


## 六、画布编辑 → 落表对照（v0.1x 起）

画布上的每个操作都在内存里记成"待导出编辑"（底部状态栏会显示摘要），点「导出 / 另存为」时由
`WarbandAmender` 一次写进 pack —— **不引入工具自己的项目层**。落表三条路子（v1.5.9 起）：

- **新增行**按"这一行属于谁"落文件：页签内容表（组 / 兵↔组 / 坐标 / 连线 / 路线）写
  `db/<表>/<项目key>_Upgrade_<页签key>`（一个页签一套；跨页路线跟 base 端；定不了页签落 `..._Upgrade_其他`；
  和包里已有文件只差大小写时并进那一份、沿用原件拼写；**文件名结尾的数字换成字母**（`SKV2`→`SKVB`、
  `EMP3`→`EMPC`，避开 RPFM「Table name ends in number」那个"只有作者本人不崩"的坑；页签 key 本身不变））；
  页签本体 / 授权 / 成本写 `db/<表>/zzzz_studio_edits`（跨页签共用；**名字排最后**，否则会被 MOD 自己的文件顶掉）；
- **已有行改值**：坐标/页签**就地改原文件**（覆盖表抢不过 MOD 自己的文件，v0.115 实测定论）；
- **删行**只能改原文件（覆盖表删不掉别人的行）：把原文件解出来、滤掉目标行、原样重编（编解码是逐字节往返验证过的）。

老包的 zzzz 覆盖表用 `probe tab-split` 一次性拆进新名字（见路线图 §六）。

| 画布操作 | 写的表与列 |
|---|---|
| 拖兵牌改坐标 | `unit_upgrade_group_ui_infos_tables` 的 `x/y`（就地改原文件；新组补 `<项目key>_Upgrade_<页签>`） |
| 卡片面板「归到页签」 | 同上表的 `category` |
| 兵种库双击 / 拖入画布 | `unit_to_unit_group_junctions_tables`（`unit`+`unit_group`）；新组还写 `unit_upgrade_groups_tables`。**这个兵已在别的组里 → 先弹确认，继续就删掉旧 junction 行（覆盖、只留这次的组）** |
| 卡片面板「删除这张兵卡」 | junction 删行；组里只剩它时等于删组 |
| 「删除整组」 | 删 `unit_upgrade_groups_tables` + junction + infos + 该组两端的 `ui_links` + 该组两端的升级路线 |
| 连接模式：点两个组 → «建立升级» | `unit_upgrade_to_unit_groups_tables`（`upgrade_key`/`base_unit_group`/`target_unit_group`/`resource_cost`/`required_rank`/`subtracted_rank`）**＋** `unit_upgrade_group_ui_links_tables`（C1：箭头读这张表），勾「互相升级」再写一条反向 |
| 连接对话框的成本 | 默认从包里已有的 `resource_costs_tables` Key 里选；选「★ 新建」则自动建 `studio_cost_<金额>` 并写 `resource_costs_tables`（`treasury_cost` **负数**，其余四列照抄包里现有成本行） |
| 点连线 → 改金额/等级 | 覆盖该 `upgrade_key` 的行 |
| 点连线 → «⇄ 交换方向» | 路线 base/target 互换（同 key 覆盖）＋ 连线方向跟着翻 |
| 点连线 → «删除这条升级» | 删路线行 + 对应连线行 |
| `Ctrl` + 把兵牌拖进右侧兵种库 | 等于删除那张兵卡（junction 删行） |
| 右键兵牌「查看已有升级…」→ 改金额/等级 | 覆盖 `unit_upgrade_to_unit_groups_tables` 里该 `upgrade_key` 的行（已有行就地改；工具新建的才写 `<项目key>_Upgrade_<页签>`，同 key 后写为准） |
| 右键「查看已有升级…」→ 交换方向（同页 + 已有连线） | 路线 base/target 互换（同 key 覆盖）＋ 连线方向跟着翻（出入口按新方向重算） |
| 右键「查看已有升级…」→ 交换方向（跨页 / 无连线） | **只改路线表**，不写也不删 `unit_upgrade_group_ui_links_tables` |
| 右键「查看已有升级…」→ 删除（跨页 / 无连线） | **只删路线表的行**，界面连线保留 |

**视角**：中键拖动平移整块画面、滚轮缩放（以鼠标为中心，25%–400%）、按 `0` 复位；
拖动兵牌时**只重画跟它相关的那几条连线**（实时跟随）。坐标换算一律除以缩放倍率，落点取整后才回传。

**序章数据归一**：原版把序章的恐虐/奸奇/基斯里夫单列成 `wh3_main_pro_sc_*` 三个亚文化（里面全是
`wh3_prologue_*` 派系，如「基斯里夫远征军」）。工具里 `_pro_sc_` 一律并回本体 `_sc_`，
且**带 prologue 的派系不算传奇**（不进单独节点，归到该种族的「通用」）——否则右侧会出现两个恐虐、两个基斯里夫。

**出入口方向**（`child_link_position`/`parent_link_position`）由两个组的相对位置自动算：
parent=升级来源（base）、child=升级结果（target）——原版实测 738/747 条连线是这个方向；
上下相邻用 3/1 或 1/3，左右相邻用 2/4 或 4/2，保证线从对着的那条边出去。

**验收**：`python verify_native.py <你的包> <原版 db.pack>` 的第 ④ 项会把上面这些操作跑一遍
（新建组+加兵、新建升级+连线、新建成本、改页签、删连线/删升级/删兵），导出后用 rpfm_cli 逐表读回核对。

### 新建分组 / 新建页签（v0.18）

- **组是绑在一起的**：拖动兵牌时同一个组的所有牌一起走（早期版本只动被拖的那张，看起来"散架"）。
- **＋新建分组**：在当前页签下建一个空组（`unit_upgrade_groups_tables` + 坐标行）。空组在画布上画成
  **虚线占位框**（"空组"），能选中、能拖走、能当连接端点；从兵种库拖兵进去时**落点落在哪个组框里就加进哪个组**
  （落在空白处才新开一组）。
- **＋新建页签**（在右侧页签列里）：输入页签 key，工具克隆母版页签的**一整套五处**结构（v0.87 起，结构清单见交接文档 §7.7）——
  1. `<hierarchy>` 里 `god_affinity_tabs` 下的 `holder_tab_<key>` 节点：**里面的按钮子节点也要换成 `<key>` 并换新 GUID**
     （以前只换外层，两个页签会抢同一个按钮组件）；
  2. `holder_tab_<key>` 组件本体（`<property name="God" value="KEY大写"/>` + "有内容才显示"的回调 + offset 槽位）；
  3. `button_toggle_tab_<key>` 组件（页签按钮：`button_upgrade_<key>.png` 是写死的路径字符串，两种斜杠都要换）；
  4. 以 key 命名的**背景面板组件** `<key name="<key小写>">`（1317×780 的 `<image>` 指向 5）；
  5. `background_images_<key>.png` 的 `<component_image>` 条目（新 GUID）；
  外加把两张图复制进包（`background_images_<key>.png` / `button_upgrade_<key>.png`）和 `unit_upgrade_group_ui_categories_tables` 加一行。
  生成后先做 **XML 良构校验**，不通过就不写。
  **标签名与图片路径用小写 key**（跟 WUU 的写法），`God` 值与 categories 行用大写 key。
- **三个必须记住的坑**（都踩过）：
  · 这份 twui 的 GUID 是 **8-4-4-16 四段写法**（如 `5a30a39e-16b0-4605-9e9cbd4dceed9771`），
    用标准五段正则去匹配会一个都匹配不到 → 新页签会和母版**撞 GUID**。工具里两种写法都认，且换新时跟随原文格式。
  · 定位母版各部分：本体块按 `id="holder_tab_XXX"`、按钮组件按 `button_toggle_tab_XXX`、
    背景面板按 `name="XXX"`、背景条目按 `imagepath="...background_images_XXX.png"`；
    **hierarchy 段和 components 段里有同名节点，按标签找必须限定从 `<components>` 之后开始找**。
  · 只属于母版的 GUID 才换新，被别处引用的共享组件 GUID（`selected_frame_general`/`button_flame`/`icon`）必须保持原值
    —— 判据是"这个 GUID 在全文出现的次数 == 在母版五处里出现的次数"。

### 种族/派系过滤 + 专属兵角标 + 背景 UI（v0.19）

- **右上选种族** → 画布自动切到该种族的页签（页签→种族是后端按"这个页签里的兵属于哪个种族"多数票算出来的），
  并显示该种族**全部**战帮兵种；**专属兵**（只有部分派系能拿到的兵）在兵牌右上角打一个黄色小三角，
  鼠标悬浮显示"专属：哪些派系"（判据：这个兵能用的派系数 < 该种族总派系数 → 209/1231 个兵是专属）。
- **右上选派系**（种族下的传奇派系条目）→ 画布只显示该派系的兵种。实测帝国：种族视图 50 张牌，瑞克领 46 张
  （差的 4 张就是别的帝国派系专属兵）。
- **拖入/双击加兵归当前页签**：新组写 `category` = 画布上选着的页签（之前写空 → 全被扔进"全部"）。
- **旧工坊的背景 UI 搬进来了**：页签背景图（`ui/skins/default/warband_upgrades/background_images_<页签>.png`，
  25 张）与 UI 区素材（`unit_card_selected_hover` / `panel_title` / `icon_treasury` 等，29 个）都从包里抽到
  `%APPDATA%\WarbandStudio\skincache`，页面用 `skins.local` 取：切页签时换背景图，左侧 322×780 的
  "游戏 UI 区"照游戏/旧工坊的样子拼出来（选中兵卡时那块显示该兵的立绘与名字）。

### 多画布 / 缓存 / 背景 UI 修正（v0.21）

- **一个包一张画布**：打开新包会**新增**画布页签（名字 = `包名 + 战帮`；原版那张叫「原版战帮」），
  点页签即在各包之间切换画布；左侧文件树**右键 →「在新画布中打开该包」**也能切/建。
- **缓存**：画布数据算一次就缓存（日志会打「走缓存」），只有**有编辑**（拖坐标、加删兵、改升级…）或**换包**时才重算；
  卡图索引 / 派系库 / 本地化各自也有一份缓存。关掉工具缓存自然消失（缓存在内存里，皮肤图缓存在 `%APPDATA%`）。
- **背景素材按包取**：`skincache/<包名>/` 一人一个目录，打开雪乃就用雪乃自己的
  `background_images_*.png`（找不到才回退到游戏原版素材），不同 mod 的画布不再互相串。
- **背景铺满整块面板**：页签背景图从 x=0 起铺 1639×780（**左边 322×780 的 UI 区也在背景图里**），
  左侧 UI 区改成透明叠加（只放兵卡框 / 兵种名 / 升级资金这些元素，不再自己铺底色）。
- **页签列按种族过滤**：选了种族只列**该种族能用的页签**；一个都没有时只提示「点下面 ＋ 新建页签」。
- **页签列滚轮**：鼠标在页签列或浮动面板上时滚轮**滚它自己**，不再缩放画布（画布缩放只在空白处生效）。

### 页签归属：严格按表单推导（v0.22）

页签属于哪些种族/派系**不做任何近似**（早先用"多数票"取一个种族，结果是**混沌勇士与四神共用页签**时，
恐虐页签被算成混沌勇士的，选恐虐就"战帮升级消失"）。现在整条链全在表单里：

```
页签(unit_upgrade_group_ui_infos_tables.category)
  → 组
  → 兵(unit_to_unit_group_junctions_tables.unit)
  → 这个兵能被哪些派系使用
      · factions_tables.military_group ↔ units_to_groupings_military_permissions_tables（军事编组）
      · units_to_exclusive_faction_permissions_tables（专属授权，allowed=true）
      · building_units_allowed_tables（建筑招募，faction + enabled）
  → 派系所属种族(factions_tables.subculture，序章 _pro_sc_ 并回本体)
```

页签的种族/派系 = 上面这条链上所有单位/派系的**并集**（`pageRaces` / `pageFactions` 都是数组），
所以一个页签可以同时属于多个种族——这正是"混沌勇士与四神共用页签"的正确表达。

- 选**种族** → 页签列只列"这个种族能用的页签"（并集里含该种族）；
- 选**派系** → 只列"这个派系能用的页签"（并集里含该派系）；该派系一条都没有时，退回它种族能用的；
  不再出现"选了派系反而冒出全部页签"；
- 画布自动切到匹配的页签，只显示该种族/派系能用的兵（专属兵打黄色角标）。

实测：选「恐虐」→ 自动切到 `KHORNE` 页签、显示 40 张牌 / 32 条连线（修复前是空白）。

### v0.27 的"画布没反应"是什么（v0.28 已修）

v0.27 我把卡片面板里的「以此为起点连接」按钮从 HTML 里删了，**但 JS 里那行
`document.getElementById('cpConnect').onclick = …` 没删** —— `null.onclick` 在脚本加载时抛 TypeError，
**它后面所有顶层语句（鼠标 mousedown/mousemove/mouseup、滚轮、键盘、拖放）全都没注册**，
所以表现成"画布完全不能交互、页签也点不动"。

修法与防呆：
- 删掉那行；并加了一条自检 —— **JS 里 `getElementById` 用到的 id 必须在 DOM 里存在**（我跑了一遍，现在无缺失）。
- 画布加了全局错误上报：`window.onerror` / `unhandledrejection` 都会以 `{type:'jsError'}` 回报到 `app.log`。
  以后画布再出问题，日志里能直接看到行号和错误信息，不用猜。

### v0.87：关页签崩溃 · 合并回归 · 页签整套结构

## 快捷键：现状与建议清单（建议部分**尚未实装**，供你挑选）

### 已实装

| 快捷键 | 作用 | 作用位置 |
|---|---|---|
| `Ctrl+Z` / `Ctrl+Y`（或 `Ctrl+Shift+Z`） | 撤销 / 重做一步（编辑集快照，每个包一套栈，最多 100 步） | 画布（有焦点时） |
| `Ctrl+A` | 选中当前页签内可见的全部组 | 画布 |
| `Ctrl` + 左键点兵牌 | 加选/取消选整组（以组为单位） | 画布 |
| 左键拖空白 | 框选（部分相交即选中） | 画布 |
| 中键拖 / 滚轮 / `0` | 平移画面 / 缩放（以鼠标为中心）/ 复位缩放与平移 | 画布 |
| `Ctrl` + 拖兵牌到右下兵种库 | 删除这张兵卡 | 画布 → 兵种库 |
| 双击兵种库里的兵 | 新开一组放到画布 | 兵种库 |
| 双击文件树里的表 | 打开表视图 | 左侧文件树 |
| 页签上 `×` / 右键页签 | 关页签 / 重命名、换图、打开、收起 | 顶部页签、画布页签列 |

### 建议（未实装，按"用起来最顺"排序）

| 建议快捷键 | 作用 | 作用位置 | 说明 |
|---|---|---|---|
| `Delete` / `Backspace` | 删除选中的组（多选就删多个） | 画布 | 与右键「删除整组」等价 |
| `Ctrl+D` | 原地复制选中的组（偏移一格） | 画布 | 做同类升级链时最省事 |
| 方向键 / `Shift`+方向键 | 选中组微调 1px / 10px | 画布 | 精确对齐用（比拖拽稳） |
| `Ctrl`+方向键 | 按 50 网格吸附移动一格 | 画布 | 与「吸附」同一套网格 |
| `空格`+拖 / 中键 | 平移画面 | 画布 | 给不习惯中键的鼠标 |
| `+` / `-` / `Ctrl+0` | 缩放 / 复位 | 画布 | 现在只有滚轮与 `0` |
| `Ctrl+G` / `Ctrl+Shift+G` | 合并选中组 / 拆开成单兵组 | 画布 | 与底部面板按钮等价 |
| `L`（或 `Ctrl+L`） | 用当前选中的两个组建升级链接 | 画布 | 与「链接」按钮等价 |
| `Ctrl+M` | 把选中组移动到页签（弹选择） | 画布 | 与右键「移动到页签…」等价 |
| `Ctrl+S` / `Ctrl+Shift+S` | 保存（导出到原包）/ 另存为 | 全局 | 现在只能点菜单/按钮 |
| `Ctrl+O` / `Ctrl+W` | 打开 pack / 关闭当前画布页签 | 全局 | 关闭时照旧问"是否导出" |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 在多个 pack 画布间切换 | 顶部页签 | 多画布时好用 |
| `Alt+↑` / `Alt+↓` | 切换画布页签栏里的上一个/下一个页签 | 画布页签列 | 页签多时比点更顺 |
| `Ctrl+F` | 聚焦兵种库搜索框（需先加搜索框） | 兵种库 | 需要配套加搜索 |
| `Enter` | 把兵种库里选中的兵加进画布 | 兵种库 | 与双击等价 |
| `Esc` | 取消选择 / 关闭浮层 / 退出右键菜单 | 全局 | 现在部分已生效 |
| `Ctrl+E` | 导出（同"另存为"） | 全局 | 与 `Ctrl+S` 二选一即可 |

> 位置原则：**画布内的快捷键只在画布有焦点时生效**（避免和左侧文件树/兵种库抢键）；
> 全局类（保存/打开/切画布）建议挂在主窗口上，任何位置都能用。
> 实装时会把这些键位同时写进「帮助」菜单，并在状态栏显示提示。
