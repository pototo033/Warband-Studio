## 二、页签归属推导链（严格按表单，不做近似）

页签属于哪些种族/派系，是**沿着这条链取并集**，每一步都是表单里的键：

```
页签 key
  └─ unit_upgrade_group_ui_infos_tables.category
       └─ 组 unit_upgrade_group
            └─ unit_to_unit_group_junctions_tables（组 → 兵）
                 └─ 兵 main_units.unit
                      └─ 这个兵能被哪些派系用
                           · factions_tables.military_group ↔ units_to_groupings_military_permissions_tables（主路）
                           · units_to_exclusive_faction_permissions_tables（allowed = true）
                           · building_units_allowed_tables（faction + enabled = true）
                                └─ 派系 factions_tables.key
                                     └─ 种族 factions_tables.subculture（_pro_sc_ 并回 _sc_）
```

**结论**：一个页签可以同时属于多个种族（混沌勇士与四神共用页签就是这么来的）。
工具里的 `pageRaces` / `pageFactions` 都是**数组**（并集），不是单选值。

## 三、节点逐个说明（作用 / 键 / 谁引用它）

| 表 | 作用 | 键 | 被谁引用 | 工具里的用法与坑 |
|---|---|---|---|---|
| `cultures_tables` | 文化（界面/音频大分类） | `key` | `cultures_subcultures.culture` | 只用来读名字 |
| `cultures_subcultures_tables` | 亚文化（建筑/兵种/Effect/外交筛选层） | `subculture` | `factions.subculture` | 名字 loc：`cultures_subcultures_name_<key>`；序章 `_pro_sc_` 要并回 |

| `units_to_groupings_military_permissions_tables` | 兵 → 军事组（授权主路） | `unit` + `military_group` | — | ★ 加兵时按种族/派系自动填：种族级填该种族所有组，派系级只填它那一个 |
| `units_to_exclusive_faction_permissions_tables` | 派系专属授权 | `key`(=unit) + `faction` + `allowed` | — | 专属兵判据之一 |
| `building_units_allowed_tables` | 建筑招募来源 | `key` + `faction` + `unit` + `enabled` | — | 专属兵判据之一 |
| `unit_upgrade_groups_tables` | 组本身 | `unit_group` | junction、infos、routes、links | 新建组时写一行 |
| `unit_to_unit_group_junctions_tables` | 兵 ↔ 组 | `unit`（★ 不唯一） | — | **拼接读**；一个兵可以同时在多个组 |

| `unit_upgrade_group_ui_categories_tables` | 页签本体的一行 | `category` | `infos.category` | 新页签要配合 twui + 两张图 |
| `unit_upgrade_group_ui_links_tables` | **游戏里画的箭头** | `child_key`（★ 不唯一） | — | **拼接读**；`parent`=base、`child`=target；出入口 1上2右3下4左 |
| `ui_features_to_cultures_tables` | 文化有没有战帮界面 | `culture` + `feature` | — | 四神要补 `WARBANDS` 行 |

## 四、待实装的新语义（本次提出，按本图落表）

1. **新建页签默认归当前种族/派系**
   - 种族级（右侧没点开具体派系）→ 给该种族**所有军事组**写授权；
   - 派系级（点开了具体派系）→ 只给它那一个军事组。
2. **「打开页签」按钮**：可以把**别的种族的页签**也加进当前画布。
   这类页签里的兵**不自动写军事组授权**，而是兵牌上打**黄色角标**（现有角标复用），
   悬浮文案改成："不属于当前军事组（可右键添加到当前军事组）"。
3. **右键菜单（组级）**：
   - 「添加到当前军事组」→ 按选中派系的 `military_group` 写 `units_to_groupings_military_permissions`；
   - 「从当前军事组移除」→ 从该表里删掉对应行（`unit` + `military_group`）。
4. **种族/派系下的页签列表**：从"只显示可用"改成**可用 + 黄标不可用**两种，都可右键改军事组。
5. **一个兵默认只在一个组**（v0.86 实装）：往画布加兵时，若这个兵已经在别的组里，先弹确认"这个兵已经被使用"，
   继续 = **覆盖之前的表单**（删掉旧的 `unit_to_unit_group_junctions_tables` 行，只留这次加入的组）；
   落回它自己所在的那个组不弹确认。注意 junction 表本身**键不唯一**（原版也有一个兵挂多组的行），
   所以**读**仍然必须拼接读，**写**由这条规则约束。

## 五、工具里的读表铁律（血泪版）

1. `unit_to_unit_group_junctions_tables`、`unit_upgrade_group_ui_links_tables`、`unit_upgrade_to_unit_groups_tables`
   这三张表**键不唯一**，必须**拼接读**（`TableFiles.ReadConcat`）；按键合并会静默吃掉行（实测连线 751→641）。
2. 删行只能改**原文件**（覆盖表删不掉别人的行）；新增走 `zzzz_studio_edits` / `zzzz_studio_layout` 覆盖表
   （**文件名要排最后**：同一张表多文件按文件名加载顺序定胜负，`studio_*` 这样的名字会被 `Yukino_*` 顶掉）；已有行的改值优先**就地改**，避免两份数据抢同一个 key。
3. 一切"归属"必须能沿本图找到依据；找不到依据先问用户，不猜。
4. **跨页的升级关系只改路线表**：两端组不在同一 `category` 时，只写 `unit_upgrade_to_unit_groups_tables`，
   **不写 `unit_upgrade_group_ui_links_tables`**（游戏按页签画坐标层，跨页的箭头画不出来；正常可见的箭头都同页）。
   「查看已有升级」面板与连接建线都按这条走；同页且已有连线的行才"路线 + 连线一起动"。
5. **一次导出内部的编辑按顺序叠加**：任何一步读表都**本轮缓冲优先**（`WarbandAmender.CurrentBytes`），
   要处理的文件清单 = 原包里的 + 本轮新写的（`TablePaths`）；键表同 key **后写为准**。
   不然"先加后删""先重命名后建页签"会互相覆盖（v0.85 修，见交接文档 §7.5）。
6. **军事组授权 / 专属授权按"组合键"合并**：`units_to_groupings_military_permissions_tables` 的真实身份是
   **(unit, military_group)**、`units_to_exclusive_faction_permissions_tables` 是 **(key, faction)** ——
   schema 的键列只标了第一列。用 `ReadMerged` + `Merge`（按键列）时，**本包的行会顶掉原版同一个兵的那一行**
   （实测：原版 5340 + 雪乃 382 → 按键合并 5394 行 vs 组合键 5531 行）。
   读这两张表用 `TableFiles.ReadComposite` + `MergeComposite`，口径 = **原版为基底 + 本包新增/覆盖重复**
   （v0.89 修，验收 ①b 盯着，见交接文档 §7.10）。


## 附：WUU 的 UI 框架（`!!!!!!TLA_warband_twui.pack`）参考

这个包只有 7 个文件（1 个 twui + 3 张 categories/features 表），但**页签的排布规则**值得照抄：

- 所有页签 **x 都是 8.00**（一列），**y 从 12 起、步长 20**（12/32/52/…/292，共 **15 个槽位**）；
- 原版四神占 12~92，各种族占 112~252，WUU 自己的子 mod 占 212/232…（**每个子 mod 占自己的槽位**）；
- 因此**多个子 mod 同时启用也不会重叠**——不是"谁 +20"地往上叠，而是**占空槽**；
- 一列 15 个槽占满时，第二列把 x 移到 **79**（8 + 按钮宽 63 + 8）。

工具的"新建页签"已按这个规则改：**从下往上找第一个空槽**（第一列优先，满了用第二列，再满就继续往下排），并在日志里打出最终 offset。
